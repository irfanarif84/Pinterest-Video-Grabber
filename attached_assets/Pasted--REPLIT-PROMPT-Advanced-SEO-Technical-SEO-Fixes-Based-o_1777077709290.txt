## CRITICAL GAP #1 — SERVER-SIDE RENDERING (HIGHEST PRIORITY)

**The problem:** The site is a pure React SPA served as a blank `<div id="root">`.
Googlebot runs JavaScript, but slowly and unreliably. React client-side routing
(`wouter`) means sub-pages like `/pinterest-gif-downloader` return the same blank
shell to crawlers — they never see unique H1s or content.

You already have a hidden `#seo-prerender` div in `index.html` with static text,
but this only covers the homepage, not the sub-pages, and the approach is fragile.

**The fix:** Add Express-based Server-Side Rendering (SSR) using React's
`renderToStaticMarkup` so every route returns fully rendered HTML.

### Step 1 — Install SSR dependencies in `artifacts/api-server/`
```bash
cd artifacts/api-server
npm install react react-dom @types/react @types/react-dom --save
```

## CRITICAL GAP #2 — CANONICAL TAGS POINT TO REPLIT DEV URL

**The problem:** Every page's canonical URL is hardcoded to `https://pinterest-video-grabber--irfanarif1984.replit.app`. When you move to a custom domain, all canonicals will be wrong and Google will treat your real domain as a duplicate.

**The fix:** Make the origin dynamic via environment variable.

### Update `artifacts/pinsave/src/lib/seo.ts`

Replace the `ORIGIN` constant line:
```typescript
// BEFORE:
const ORIGIN = "https://pinterest-video-grabber--irfanarif1984.replit.app";

// AFTER:
const ORIGIN = import.meta.env.VITE_SITE_ORIGIN || "https://pinterest-video-grabber--irfanarif1984.replit.app";
export const ORIGIN_URL = ORIGIN;
```

Also update the `ssr/pages.ts` file:
```typescript
// BEFORE:
export const ORIGIN = "https://pinterest-video-grabber--irfanarif1984.replit.app";

// AFTER:
export const ORIGIN = process.env.SITE_ORIGIN || "https://pinterest-video-grabber--irfanarif1984.replit.app";
```

Add to your Replit Secrets (environment variables):
- `VITE_SITE_ORIGIN` = `https://pinterest-video-grabber--irfanarif1984.replit.app` (update when you get a custom domain)
- `SITE_ORIGIN` = same value

## CRITICAL GAP #3 — SITEMAP MISSING SUB-PAGES' JSON-LD SCHEMAS

**The problem:** Sub-pages (GIF, Image, MP3, HowTo) each have unique `usePageSEO()` calls that update the `<title>`, `<meta>` tags, and canonical in the browser — but they have NO JSON-LD schema blocks of their own. Google Rich Results require schema per-page.

**The fix:** Add per-page JSON-LD to each sub-page component.

### In `artifacts/pinsave/src/pages/GifDownloader.tsx`

After the `usePageSEO()` call, add this inside the `<>` before `<SiteHeader />`:

```tsx
useEffect(() => {
  // Inject page-specific JSON-LD
  const id = "ld-gif-page";
  if (!document.getElementById(id)) {
    const script = document.createElement("script");
    script.id = id;
    script.type = "application/ld+json";
    script.text = JSON.stringify({
```

## GAP #5 — MANIFEST.JSON MISSING PROPER PNG ICONS

**The problem:** `manifest.json` only references `favicon.svg`. Chrome on Android and iOS PWA install prompts require proper raster PNG icons at specific sizes. Without them, the PWA install prompt is suppressed and the site gets a lower PWA score.

**The fix:** Create PNG icons and update the manifest.

### Create icons using Node.js in `artifacts/pinsave/`

Add this script to `artifacts/pinsave/package.json` scripts:
```json
"generate-icons": "node scripts/generate-icons.mjs"
```

Create `artifacts/pinsave/scripts/generate-icons.mjs`:
```javascript
// Generates PNG icons from the SVG favicon using sharp
import sharp from "sharp";
import fs from "fs";
import path from "path";

const SVG_PATH = "./public/favicon.svg";
const OUT_DIR = "./public/icons";
const SIZES = [72, 96, 128, 144, 152, 192, 384, 512];

if (!fs.existsSync(OUT_DIR)) fs.mkdirSync(OUT_DIR, { recursive: true });

const svgBuffer = fs.readFileSync(SVG_PATH);

for (const size of SIZES) {
  await sharp(svgBuffer)
    .resize(size, size)
    .png()
    .toFile(path.join(OUT_DIR, `icon-${size}x${size}.png`));
  console.log(`Generated icon-${size}x${size}.png`);
}
```

Run: `cd artifacts/pinsave && npm install sharp --save-dev && npm run generate-icons`

### Update `artifacts/pinsave/public/manifest.json`

Replace `"icons"` array with:
```json
"icons": [
  { "src": "/icons/icon-72x72.png",   "sizes": "72x72",   "type": "image/png" },
  { "src": "/icons/icon-96x96.png",   "sizes": "96x96",   "type": "image/png" },
  { "src": "/icons/icon-128x128.png", "sizes": "128x128", "type": "image/png" },
  { "src": "/icons/icon-144x144.png", "sizes": "144x144", "type": "image/png" },
  { "src": "/icons/icon-152x152.png", "sizes": "152x152", "type": "image/png" },
  { "src": "/icons/icon-192x192.png", "sizes": "192x192", "type": "image/png", "purpose": "maskable" },
  { "src": "/icons/icon-384x384.png", "sizes": "384x384", "type": "image/png" },
  { "src": "/icons/icon-512x512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" },

```

## GAP #6 — SITEMAP IS STATIC, NOT DYNAMIC

**The problem:** `sitemap.xml` is a static file with a hardcoded date (`2026-04-25`). It will never update automatically, and `lastmod` accuracy matters for crawl prioritization.

**The fix:** Serve the sitemap dynamically from Express so `lastmod` always reflects today's date and you can easily add new pages.

### Add to `artifacts/api-server/src/routes/index.ts`

```typescript
import sitemapRouter from "./sitemap";
router.use("/", sitemapRouter);
```

### Create `artifacts/api-server/src/routes/sitemap.ts`

```typescript
import { Router } from "express";
const router = Router();
const ORIGIN = process.env.SITE_ORIGIN || "https://pinterest-video-grabber--irfanarif1984.replit.app";
const TODAY = new Date().toISOString().split("T")[0];

const PAGES = [
  { loc: "/",                                   priority: "1.0", freq: "weekly"  },
  { loc: "/pinterest-gif-downloader",           priority: "0.9", freq: "monthly" },
  { loc: "/pinterest-image-downloader",         priority: "0.9", freq: "monthly" },
  { loc: "/pinterest-to-mp3",                   priority: "0.9", freq: "monthly" },
  { loc: "/how-to-download-pinterest-videos",   priority: "0.8", freq: "monthly" },
  { loc: "/about",                              priority: "0.4", freq: "yearly"  },
  { loc: "/privacy-policy",                     priority: "0.3", freq: "yearly"  },
  { loc: "/terms-of-service",                   priority: "0.3", freq: "yearly"  },
];

router.get("/sitemap.xml", (_req, res) => {
  res.header("Content-Type", "application/xml");
  res.header("Cache-Control", "public, max-age=86400");
  const urls = PAGES.map(p => `
  <url>
    <loc>${ORIGIN}${p.loc}</loc>
    <lastmod>${TODAY}</lastmod>
    <changefreq>${p.freq}</changefreq>
    <priority>${p.priority}</priority>
    <xhtml:link rel="alternate" hreflang="en" href="${ORIGIN}${p.loc}"/>
    <xhtml:link rel="alternate" hreflang="x-default" href="${ORIGIN}/"/>
  </url>`).join("");
  res.send(`<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"
        xmlns:xhtml="http://www.w3.org/1999/xhtml"
        xmlns:image="http://www.google.com/schemas/sitemap-image/1.1">
${urls}
</urlset>`);
});

router.get("/robots.txt", (_req, res) => {
  res.header("Content-Type", "text/plain");
  res.send(`User-agent: *
Allow: /
Disallow: /api/
Disallow: /admin/
Disallow: /private/

Sitemap: ${ORIGIN}/sitemap.xml
Sitemap: ${ORIGIN}/sitemap-images.xml

User-agent: AhrefsBot
Crawl-delay: 10

User-agent: SemrushBot
Crawl-delay: 10

User-agent: MJ12bot
Crawl-delay: 10`);
});

export default router;
```

## GAP #10 — FONT LOADING BLOCKS RENDER (LCP IMPACT)

**The problem:** Google Fonts are loaded with a synchronous `<link rel="stylesheet">` in `index.html`. This blocks rendering until fonts are fetched, directly hurting LCP score.

**The fix:** Update font loading in `artifacts/pinsave/index.html`:

```html
<!-- BEFORE: -->
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:opsz,wght@9..40,400;9..40,500;9..40,600&family=Syne:wght@600;700;800&display=swap" rel="stylesheet" />

<!-- AFTER: non-render-blocking -->
<link rel="preload" href="https://fonts.googleapis.com/css2?family=DM+Sans:opsz,wght@9..40,400;9..40,500;9..40,600&family=Syne:wght@600;700;800&display=swap" as="style" onload="this.onload=null;this.rel='stylesheet'" />
<noscript>
  <link href="https://fonts.googleapis.com/css2?family=DM+Sans:opsz,wght@9..40,400;9..40,500;9..40,600&family=Syne:wght@600;700;800&display=swap" rel="stylesheet" />
</noscript>
```

Also add `font-display: swap` in `artifacts/pinsave/src/index.css` if you have any `@font-face` declarations.
